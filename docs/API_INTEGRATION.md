## 계약·노출 범위

- 세무 문서 상세는 같은 필드가 포함된 목록 응답을 사용한다. 미통과 시 파일 선택창에서 새 서류를 업로드하며, 비교 요청의 장애는 명시적으로 재시도한다. 완료된 비교는 서버 캐시에서 복원한다.
- 뉴스 목록은 커서 기반 무한 스크롤을 사용하고 다음 응답을 기다릴 때 하단 스켈레톤을 표시한다. 필터·종목 변경은 진행 중인 이전 요청을 취소한다.
- 채팅 메시지는 `afterSequence`로 끝까지 조회한다. 방 검색 목록은 서버 계약상 최대 100개다.
- 가입의 FSC 고지는 `fscDisclaimerAccepted`로 제출하고 서버 감사 이벤트에 문서 버전·동의 시각을 기록한다. 과거 계정의 동의를 추정해 추가하지 않는다.

## 대체 경로를 사용하는 API

- 본문형 로그인·refresh·logout은 네이티브/과거 검증 클라이언트용이며 현재 브라우저는 쿠키 전용 경로를 사용한다.
- 종목 `/history` 대신 `/chart`, 단독 뉴스 용어 해설·공시 `/questions` 대신 인용을 저장하는 K-Agent 메시지 흐름을 사용한다.
- 개별 공시 섹션 번역 API 대신 전체 문서 번역 요청·조회로 원본 HTML 구조를 유지한다.

API가 존재한다는 사실만으로 UI 연결 완료나 외부 공급자·모델의 실시간 성공을 의미하지 않는다. 모든 Backend 기능이 현재 Frontend에서 사용 가능하다는 판정은 하지 않는다.

## 공통 표시·오류 정책

- 뉴스·공시의 목록 및 상세 시간은 EN/KR 모두 한국 시간대의 24시간제와 `KST`로 표시한다. 뉴스 메타 정보에는 언론사·발행 일시만 표시하며 자동 번역/원문 상태 문구는 붙이지 않는다. 본문 번역·요약의 로딩과 오류 처리는 유지한다.
- 뉴스·공시 상세의 원문 열기는 외부 링크 아이콘과 `#EDECE5` 버튼을 공통 사용한다. 뉴스는 제목 아래 출처·시간 다음에 배치하며 Backend 원문 URL을 새 창에서 연다. HTTP(S) URL만 허용하고 `noopener noreferrer`를 적용한다.
- 외국인 한도 종목은 장중·장외 모두 예측을 표시한다. Backend의 `targetDate`·`predictionSession`을 검증하여 장중/다음 장 예측과 대상일을 표기하며, `baseDate`를 예측일로 간주하지 않는다. 장중 1분·장외 5분마다 보이는 화면만 갱신하고 개장·마감 시 즉시 재조회한다. 대상일 예측이 미완료면 직전 보유율을 유지한다.
- 홈 제목·바로가기는 순차 등장하며 보유율 게이지는 화면에 처음 들어올 때 채워진다. 모션 감소 설정에서는 즉시 최종 상태를 표시한다. 관심종목 하트는 종목명과 별도 정렬 영역에서 수직 중앙에 배치한다.
- Home `394:1156`, 검색 `264:3322` 기준의 화면 구조와 기존 원본 에셋을 사용한다. 긴 회사명은 실제 너비에 맞춰 축소하며 공시 제목은 줄바꿈·행 중앙 정렬을 사용한다. 홈·검색·전체 공시의 점과 라벨은 같은 감성 분류를 사용한다.
- 검색 결과는 최대 75개 지원 종목을 조회하고 4개씩 한 종목 단위로 이동한다. 첫/마지막 위치에서 해당 화살표의 동작과 아이콘을 함께 비활성화한다.
- 검색·종목 가격과 변동은 EN USD/KRW, KR KRW/USD 순서다. 환율 누락을 원화 숫자에 달러 기호를 붙여 감추지 않는다.
- 가입 비밀번호는 8~128자 영문·숫자·특수기호 조합이다. 대문자 필수 조건은 없다.
- 홈 조약세율의 미지원 국가 영역은 흐림 처리를 유지하고 지원 범위 안내를 그 위에 표시한다. 표 아래의 일반 세율 고지는 카드 테두리와 분리한다. 흐림 행에는 실제 세율처럼 보이는 임의 수치를 넣지 않는다.
- 보호 요청이 세션 갱신 뒤에도 401이면 로그인으로 이동한다. 통신 실패 또는 실제 Backend 연결 실패로 확인된 게이트웨이 장애만 서버 연결 안내 화면으로 이동한다. 일반 업무 오류·취소 요청은 현재 화면에서 처리하며 실패한 쓰기 요청을 자동 재전송하지 않는다.

- 로컬 Frontend에서 배포 Backend로 새 계정 가입, 로그인, 내 정보 새로고침·연속 재접속, 동시 탭 세션 복원, 로그아웃 후 비로그인 상태를 확인했다.
- 실제 채팅방 생성·이름 변경·검색·삭제와 최근 본 공시 기록, 관심종목 가격·개인화 피드 표시를 확인했다. QA에서 만든 임시 대화만 삭제했다.
- EN/KR 회원 화면과 375px 가입·내 정보 화면을 확인하고 긴 ID의 모바일 레이아웃 붕괴를 수정했다.
- 9월 3일 추가 검증: Frontend 73개·빌드, Backend 264개 중 258개 통과·외부 원문/스냅샷 선택 감사 6개 생략, AI 187개·Ruff·Mypy, 이미지·환경 보존 6개 검사 통과.
- 로컬 5173→배포 Backend에서 검색 10종목의 첫/중간/마지막 화살표, EN/KR 가격·변동 전환, 긴 종목명 축소, 공시 중앙 정렬·점 간격을 확인했다. 375px/768px 실제 페이지는 가로 넘침과 숨겨진 공시 제목이 0개다. 서버 연결 안내에서 실제 정상 API 확인 후 원래 검색 경로 복귀를 검증했다.
- 제한 4종목의 실제 다음 거래일 예측, 비제한 종목의 예측 제외·직전 보유율 유지, 375px 종목명의 하트 중앙 정렬과 게이지 스크롤 진입 애니메이션을 확인했다. 뉴스·공시 원문 버튼의 배경색·외부 링크 아이콘·새 창 속성과 24시간 KST 표기를 확인했다.
- 메모리만 보관하던 refresh 자격 증명, 회전 시 다른 탭의 access 토큰 조기 무효화, 갱신 응답 유실 후 중복 회전 문제를 각각 수정·회귀 검사했다. 원격 미리보기와 운영 main 배포 완료는 이 로컬 연동 검증과 구분한다.
# 세무 사전 점검 결과

- 계정 표시: `GET /api/v1/me`의 `nationality`, `investorType`, `taxVerificationStatus`를 사용한다. 상태는 `NOT_STARTED`, `IN_PROGRESS`, `VERIFIED`로 표시한다.
- 완료 문서: `GET /api/v1/me/tax-review-package`와 `GET /api/v1/me/tax-review-package/correction.pdf`를 사용한다. 원본 3종은 기존 본인 문서 원본 API에서 읽는다.
- `/tax/review`의 이미지·PDF는 인증 후 메모리 Blob으로 자동 표시하고 화면 종료 시 해제한다. 편집·제출 기능은 제공하지 않는다.
